## 1. FINDINGS' traps

### T1. Template mismatch

- **What:** Voyager's chat endpoint rendered `olmo3-7b-think` with the Olmo 3 *Instruct* template, whose generation prompt has no `<think>`.
- **Found:** Oct 21 from prompt-token counts. On a plain question the server counted 178 tokens: the Instruct template's exact count. All 24 revisions of the Think template give 215.
- **Fix:** Render the official Think template ourselves and send it to `/v1/completions`. Every earlier Voyager run of this model is in the Instruct format (F2).
- **Source:** `results/summaries/trackA/template_revisions.json`.

### T2. Default system prompt

- **What:** The two templates carry different default system prompts. Declaring the tool in the system prompt changed hint following on the inserted tool turn: 34 of 60 [44, 68%] vs 24 of 60 [29, 53%], **+17 points [+3, +30]**.
- **Found:** —
- **Fix:** Every record names its system prompt. Training uses the declared version; held-out evaluation keeps both.
- **Source:** `base_format_runs.jsonl` (`system_prompt`).

### T3. Model-ID routing

- **What:** On Oct 21 Voyager replaced its six IDs with family IDs plus `reasoning_effort`, and the default effort serves the *Instruct* model.
- **Found:** —
- **Fix:** One name → (ID, effort) map. A Think model sent without an effort is refused, and the catalog is checked at the start of each run.
- **Source:** `archive/superseded/OVERVIEW_2026-10-27.md` §5; commit `280bd12`.
- Rerun: the 11 Step 2b runs saved before the change.
- Same-checkpoint check on the new route: - max difference 0.0003 on the first 2,047 tokens - beyond them, 24 top-token mismatches, all near-ties - the Instruct model gave 654 mismatches

### T4. Parser forms

- **What:** "**Answer**: D" and "the **answer** is E" weren't read. Found in a Step 4 continuation.
- **Found:** —
- **Fix:** Re-scoring every saved result changed 1 letter: a Step 4 hint-arm continuation went from no answer to D, the hint letter. The hint arm now ends on the hint 44 of 57 (was 43).
- **Source:** Commits `b0331ed`, `5bbd7c0`.

### T5. "expected" false matches

- **What:** The tool-mention words included plain "expected", which matched 7 sentences that weren't about the hint ("the expected value") among those planned for deletion.
- **Found:** —
- **Fix:** Narrowed to "expected answer" / "expected_answer" / "expected is" / "expected: (X)" for Step 4, Step 10 and F8. Step 3's mention counts (F6) still use the broader words.
- **Source:** Commit `5559a3d`; `finetune/look/deletion.py` (`HINT_TOOL`).

### T6. Identity canary

- **Found:** On Oct 22 a network error was logged as a failed check. Now a canary that gets no reply is no verdict: requests pause, it retries every 2 minutes, and the run halts only on a real mismatch or after 30 minutes unreachable.
- **Fix:** —
- **Source:** `results/summaries/voyager_canary.jsonl`; commit `58dcf97`.
- Since then: 47 of 47 checks with a reply passed (Oct 22–26).

### T7. Averaging a cumulative curve by layer type

Averaged over the 8 full vs the 24 sliding layers, it gave 0.53 vs 0.65 at cut (ii), which reads as "[quote]". Those averages describe the step's position, not which layers do the reading.
- **Found:** —
- **Fix:** The per-layer drop and its share of the total (F11): 0.95 at the full layers.
- **Source:** `step10_by_layer_type.json` (the first reading, kept) vs `step10_handoff.json`.

### T8. A weights check that didn't check

- **What:** Step 8's snapshot check read the hash from the cache's link names. On Sol the weight files are regular files, so it reported `weights_same: false` without hashing anything. Its summary line, "FAIL on 0 of 5", also counted passes.
- **Found:** —
- **Fix:** Regular files are now hashed (sha256 for the weights, the git blob id for the rest) and the result is cached. The line counts failures. The Sol weights were checked by `sha256sum` (F9).
- **Source:** `finetune/gpu/kit.py` (`files_vs_template_rev`), `checkpoint_check.py` (`verdict`).

### T9. An anchor picked where the hint is strongest (the second time)

- **What:** Step 9's first aligned reading compared followed runs at the takeover with resisted runs at their closest approach, which is by construction where the hint letter peaks. It read "[quote]": −0.0076 [−0.0123, −0.0016].
- **Found:** —
- **Fix:** Anchor both groups the same way: every lead onset after the first fifth, lasting or temporary. Temporary leads in followed and resisted runs then don't differ: −0.7e-3 [−4.2e-3, +2.0e-3] (F10, F14).
- **Source:** `step9_followup.json` (`aligned`, kept and marked biased; `onsets_matched`).
- The first time: was before Step 4 (analysis 2(a), Oct 25). "[quote]" came out +50 points, partly built in: just before a takeover the hint can't lead. Matched onsets gave −1 point [−16, +19] (F5).
- Rule: No comparison anchors one group on a point chosen by the measure being compared.

### T10. A context window that silently drops the question (Ollama)

- **What:** Ollama's default context is 4,096 tokens with context shift on: once a run's conversation passed it, Ollama dropped the conversation's start (the question and the hint) without an error, and the model kept answering. The first 20 Track B rows from Ollama (qwen3:8b) ran this way; 13 of them passed 4,096 tokens (prompt + reply).
- **Found:** —
- **Fix:** Every request sets the context to 33,792 (the 32,768 budget plus room) and each row records it; a row counts as done only with the current context, so the 20 rows are rerun (`8d8e206`).
- **Source:** `providers/ollama.py` (`NUM_CTX`), `progress/run_trackB.py` (`current()`).
- Rule: A local server's context is set explicitly and recorded per row; a row made under another context doesn't count.

### T11. A "same-day" rerun replayed from the reply cache (B16)

- **What:** B16 reran Track B's tool arms beside its new arm so the comparison would be made the same day. The requests were exactly Track B's (prompt, seed, budget), and `client.py` caches every reply keyed by the full request, so 907 of 972 came back as Track B's Oct 27–28 replies (Olmo's in 0.2 s). The pre-registered drift check then reads 0 by construction.
- **Found:** Nov 1 when the drift check read +0 [+0, +0] for two models: every replayed record's final and private text equals Track B's. Only 508 new cache entries were written during B16, about the authority arm plus the 65 tool runs that were not replays.
- **Fix:** Reported as cross-day (F35), with the canary's record that the served models were unchanged. C16's same-day control is not affected: none of its 200 reviews repeats an earlier request.
- **Source:** `cot-disclosure/client.py` (`_request`, the cache), the Nov 1 10:45 and 20:50 session logs.
- Seen before: Track C met the same thing on Oct 30 (C18's re-review matched C16's exactly; TRACK_C's known traps: "repeats need new seeds"): an identical request is answered from the cache. B16's design didn't carry that over.
- Rule: A rerun meant as a same-day control sends a new seed or bypasses the cache (`use_cache=False`), and its pre-registration says which.
- Checked: B19 (Nov 1) did both: 972 new runs, the cache unchanged, B16's six readings the same (F35).
