**Speaker notes:**

55 seconds.

The question is the same: when a wrong hint changes a model’s answer, does the model admit it used the hint? A hint is extra text pointing to a wrong answer. A user hint is the user writing “I think the answer is C”, as in the 2023 base paper. A tool hint is the same letter in text that looks like the output of an answer-key tool. So far we pasted that text into the user’s message; in the next phase the model will actually call a tool that returns it, which is how agents receive information from search, databases or documents.

What is new compared with 2023: thinking models, where we check the private reasoning and the final answer separately; tool hints; and, as next steps, agents that check each other and a fine-tuned model that resists wrong hints.

Why each change:
• Models: the feedback asked for exact checkpoints; thinking replies are 3 to 4 times longer and Qwen3 235B was too slow. Six models still cover two families, two sizes and two designs. Both families are open, so we can look inside and fine-tune them.
• Questions: generated puzzles cannot be memorized and have exact answers, but they were too easy, so we added harder exam questions.
• Runs: the feedback asked for repeated no-hint runs (to measure chance changes), hint letters spread evenly over the options (so a favorite letter is not mistaken for hint-following), and correct hints (to tell “follows hints” from “confused by any hint”).
• Scoring: the feedback asked us to separate mentioning a hint from admitting it changed the answer; keywords cannot do that, so we label by hand. The LLM judge is not built yet.
• Thinking cannot be switched off on Voyager; our plan is on the next-steps slide.

**Speaker notes:**

75 seconds.

Left, Test 1: 24 easy puzzles with a user hint. Only the smallest instruct model followed it, 5 of 48 times. Without a hint, no model ever chose those letters. The bigger models solved almost every puzzle, so the hint had no room.

Right, Test 2: harder exam questions each model was unsure about. Grey is the user hint, pink is the same wrong letter as a tool hint. The instruct model follows both. The two thinking models mostly ignore the user hint but follow the tool hint.

What we conclude: hints work when the model is unsure; thinking models trust a tool far more than the user, 17 of 31 versus 2 of 31; and they keep it private: the private reasoning mentioned the hint in 208 of 216 puzzle runs, the final answer in only 8.

The pink box shows how the hint changes the reasoning in one real run. The model’s own calculation does not match any option. It reads the tool hint, decides there must be a different calculation, and lands on G. The final answer shows only the clean calculation. Why this can happen: the model reads every earlier word, including the hint and its own earlier sentences; once its reasoning repeats the hint, the rest of the reasoning builds on it. We will test this inside the model in the next steps.

Limits: only two model families so far, a small Test 2, and keyword counts.

## Slide 5: 4 · Risks and obstacles

**On the slide:**

- Four issues, each with a plan.
- 1
- Too few models to generalize
- What we saw  Test 2 used two thinking models (Olmo 3 7B Think, Qwen3 30B Thinking), 11 to 20 questions each, one run each, and a pasted tool hint. Voyager cannot switch thinking off.
- Plan  Track A: more and widely used thinking models, including DeepSeek V4 Flash (thinking on/off, about $2 per 1,000 calls) and Qwen3 in Ollama (free); 3 runs per question; real tool calls.
- 2
- Keyword counts are rough
- What we saw  “The user” also appears in replies with no hint (22 of 72 for Olmo 3 7B Think). A keyword cannot tell “the user says E, but it is D” from “the user says E, so E”.
- Plan  Two of us label each reply by hand (101 ready) and report how often we agree.
- 3
- Long replies get cut off, and can leak
- What we saw  Olmo 3 7B Think hit the 16,000-token limit in 13 of 60 hard runs. Cut-off replies that were not streamed showed the private reasoning in the answer (8 of 8; streamed: 0 of 8).
- Plan  Raise the limit for that model, always stream, and count cut-off replies as unanswered.
- 4
- The fine-tuning step needs GPUs and could backfire
- What we saw  GPU access on ASU’s Sol is not confirmed yet. Training a model to mention hints could teach it to hide them instead.
- Plan  Request Sol now; train small adapters (LoRA) on a 7B model, which fits one GPU. Judge success by behavior: does the answer still follow the hint?

**Speaker notes:**

Three tracks.
Track A asks whether this holds beyond Olmo and Qwen. We run the same tests on more thinking models, including DeepSeek V4 Flash, which can switch thinking on and off in one model, and we replace the pasted tool hint with a real tool call.
Track B is the multi-agent pipeline. A solver agent answers using a lookup tool that sometimes returns a wrong answer. A reviewer agent checks the answer, and we vary what it can see.
