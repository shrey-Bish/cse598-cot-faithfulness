## 4. What it means, as A40's log said in advance (§9)

> **Fewer, but costs acceptance:** A40 follows fewer wrong hints by **ignoring hints**, the correct ones too. This is
> the risk in §4, and the paper's Table 12 seen on our measure. Consistency costs the hint's value when it is right.
> Reported as a trade, not as a fix.

- **So A40 doesn't beat the instruction by its rule.** It follows the wrong hint in 12% of runs against the
  instruction's 33%, and takes the correct hint in 76% against 91%.
- **Against LoRA** the same trade appears: *fewer, but costs acceptance*.
- **R1 passes,** so A40 is a fix against base by Gate 3's rule, as the four trained versions were on the 30 (F28).
  This one is on E2's 120 questions.

## 6. The counting bug found today (no reading depends on it)

- **On Sol, `--runs-left` said A39's E2 had 54 runs left** (base 27, prompt_only 1, lora 6, lora_note 20) when every
  run has an ok record.
  - `eval.runs_files` lists the whole-system file first, then the parts by name, and the resume and the feeder took
    the last record of any status. So an older `not_run` in a part, listed later, hid a sweep's `ok`.
  - The same naming can hide B1R2's sweeps (`p<k>of4` sorts before parts 5, 9, 21, … of 40).
- **The readers were never affected.** `a39.py`, `a40.py` and `a42.py` count a run once it has any ok record and keep
  its last ok record.
- **The fix** (the 13:15 log's §4, with tests seen failing first): `eval.done_ids` (any ok record counts) for the
  resume, the feeder and `plan_eval`, and `provenance_job.ok_rows` (each run's last ok record) for B1R2's report. On
  B1's and Gate 3's saved runs it changes no run (824 and 5,580; 0 differ), so F38 and F28 stand.
